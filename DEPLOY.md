# Запуск программы в интернете (для учеников с телефонов и компьютеров)

Программа не требует сторонних библиотек — только Python 3 и один файл базы данных SQLite (`app.db`). Все конфиги уже лежат в корне репозитория.

> **Важно:** храните папку с базой (`/app/data`) на постоянном диске (Persistent Disk / Volume), чтобы аккаунты и оценки учеников не пропадали при перезапуске.

---

## Перед публикацией: три обязательных шага

1. **Зарегистрируйте владельца сразу после первого деплоя.** Первый зарегистрировавшийся становится владельцем — не оставляйте ссылку без присмотра до этого момента.
2. **Включите HTTPS-флаг cookie:** переменная `SECURE_COOKIES=1` (на Render/Railway TLS уже есть). Иначе cookie сессии может уйти по открытому HTTP.
3. **Не отключайте `TRUST_PROXY` на облаке.** `TRUST_PROXY=1` нужен, чтобы ограничение попыток входа работало по реальному IP клиента. Если сервер открыт в интернет напрямую (VPS без прокси), наоборот выставьте `TRUST_PROXY=0`, иначе клиент подделает свой IP.

---

## Вариант 1. Render (проще всего)

1. Загрузите репозиторий на GitHub.
2. Зайдите на [render.com](https://render.com) → **New → Blueprint** и выберите репозиторий.
3. Render автоматически подхватит `render.yaml` (Docker + постоянный диск `/app/data` на 1 ГБ).
4. После сборки вы получите постоянную ссылку вида `https://chinese-learning-app.onrender.com` — её можно отправлять ученикам.

---

## Вариант 2. Railway

1. Загрузите репозиторий на GitHub и откройте [railway.app](https://railway.app) → **New Project → Deploy from GitHub repo**.
2. Railway подхватит `Dockerfile` и `railway.toml`.
3. В настройках сервиса добавьте **Volume**, смонтированный в `/app/data`, и переменную `DB_PATH=/app/data/app.db`.
4. В разделе **Settings → Networking** нажмите **Generate Domain** и получите публичную HTTPS-ссылку.

---

## Вариант 3. Свой VPS / компьютер (Docker)

```bash
docker build -t chinese-app .
docker run -d \
  --name chinese-app \
  --restart unless-stopped \
  -p 8080:8080 \
  -e SECURE_COOKIES=1 \
  -e TRUST_PROXY=0 \
  -v chinese_data:/app/data \
  chinese-app
```

`TRUST_PROXY=0` здесь важен: контейнер слушает порт напрямую, прокси перед ним нет.

Или без Docker напрямую через Python 3:

```bash
python3 build.py
python3 -u server.py
```

## ИИ-репетитор (необязательно)

Без ключа приложение работает полностью — репетитор просто отвечает в локальном режиме из готовых подсказок. Чтобы включить настоящую модель, добавьте переменные:

```
AI_API_KEY=sk-...            # или OPENAI_API_KEY
AI_MODEL=gpt-4o-mini         # по умолчанию
AI_BASE_URL=https://api.openai.com/v1
```

Эндпоинт `/api/tutor/chat` требует входа в аккаунт и имеет квоту на пользователя (40 запросов в час), чтобы ключ нельзя было использовать как бесплатный прокси.

### Поиск в источниках

Помощник умеет искать слово вне курса: локальный словарь `data/cedict.txt.gz`
(11 470 слов, едет в образ — см. `Dockerfile`) работает всегда, а Викисловарь и
Tatoeba включаются переменными:

```
SOURCES_ONLINE=1     # 1 по умолчанию; 0 — ни одного запроса в интернет
SOURCES_TIMEOUT=6    # таймаут одного обращения, секунды
CEDICT_PATH=data/cedict.txt.gz
```

Если внешние словари недоступны, ответ не ломается: остаётся локальный словарь,
а под ответом — ссылки «где проверить» (MDBG, 汉典, Викисловарь). Общая квота —
200 обращений в час на сервер, ответы кэшируются на 6 часов. Файл словаря
включён в исключение `.gitignore` и копируется в образ отдельной строкой
`COPY data/cedict.txt.gz`; собирается скриптом `tools/make-dict.py` из CC-CEDICT (CC BY-SA 3.0) и
`drkameleon/complete-hsk-vocabulary` (MIT); русские значения подставлены
из карманного словаря курса — их пересобрать можно так:

```
python3 tools/make-lexicon.py   # карманный словарь → src/lexicon.js
python3 tools/make-dict.py      # серверный словарь → data/cedict.txt.gz
```

## Пароли

- Минимальная длина пароля — 8 символов (проверяется на сервере).
- Ученик меняет пароль сам в разделе «Профиль».
- Если ученик забыл пароль, учитель открывает его карточку в «Классе» и нажимает **«Сбросить пароль»** — приложение покажет временный пароль, его нужно передать ученику.

## Резервные копии

Владелец может скачать копию базы прямо из приложения: **«Система» → «Скачать резервную копию (app.db)»**.

Дополнительно настройте автоматический бэкап на стороне хостинга — снапшоты диска у Render/Railway или `cron` + копирование `app.db`. SQLite работает в режиме WAL, поэтому для копирования «на горячую» используйте `sqlite3 app.db ".backup backup.db"`, а не `cp`.

## Ошибка «attempt to write a readonly database»

Так падает контейнер, если база лежит на диске, к которому у процесса нет прав на запись. Причина типовая: **Render Disk / Railway Volume монтируется в `/app/data` уже после сборки образа и принадлежит `root`**, а сервер работает от непривилегированного пользователя `appuser` (uid 10001).

В образе это уже решено: `docker-entrypoint.py` запускается от root, выдаёт `appuser` права на каталог данных, проверяет реальную возможность записи и только потом запускает сервер от непривилегированного пользователя — приложение само root'ом не работает. Если контейнер стартует не от root (Kubernetes с `runAsNonRoot`), скрипт просто запускает сервер, ничего не меняя.

Если вы запускаете **без Docker** (просто `python3 server.py`) и видите эту ошибку:

```bash
sudo chown -R "$(id -u):$(id -g)" data/
# и убедитесь, что диск смонтирован не в режиме read-only
```

Проверить, под каким пользователем и с какими правами работает сервис, можно в «Класс» → «Состояние системы» (только владелец) и в логах запуска.

## Обновление версии

1. `git pull`
2. Пересоберите образ (или `python3 build.py` при запуске без Docker).
3. Перезапустите сервис.

Схема базы обновляется автоматически при старте (`PRAGMA user_version`), данные не теряются.

---

После запуска откройте сайт, зарегистрируйтесь первым (вы сразу станете **Владельцем**), затем зайдите в **«Класс» → «Создать код»** и раздайте коды ученикам.
